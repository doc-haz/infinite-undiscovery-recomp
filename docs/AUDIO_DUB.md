# Audio assets & fan-dub — technical guide

> How to locate *Infinite Undiscovery*'s audio, identify the dialogue **per
> character**, and incorporate re-recorded lines in another language as a
> **dubbing mod**. Deep reverse-engineering detail lives in
> [`docs/re/audio-dub.md`](re/audio-dub.md); this document is the practical,
> step-by-step procedure.

---

## 1. Where the audio lives

Both EU/PAL discs are **XGD2** Xbox 360 DVDs. The XDVDFS filesystem holds only
four files; all content is inside two monolithic containers:

```
/$SystemUpdate/…          (system update)
/default.xex              (signed, encrypted XEX2)
/ud1.bin                  (~2.21 GB)
/ud2.bin                  (~2.80 GB)
```

`ud1.bin` / `ud2.bin` are sequences of self-describing **NORM/MRON** archives
laid end to end on 2048-byte boundaries, with unrelated blobs (video, compressed
blocks, audio) filling the gaps. There is no global table of contents.

Two kinds of audio exist:

1. **`SOND` resources inside the archives** — the `AAC ` containers that hold
   sound effects, foley and the **voice acting** (line by line). These are the
   files present in the extracted trees (`extract/f2/all_d1ud1`, `all_d1ud2`).
2. **Bare `AAC ` containers in the gaps between archives** — the **music**.
   They are *not* archive entries and therefore are *not* in the extracted
   trees.

| Container | `SOND` entries | real banks | sounds | duration |
|---|---:|---:|---:|---:|
| disc 1 `ud1.bin` | 1275 (445 empty) | 830 | 22,243 | 257.7 min |
| disc 2 `ud2.bin` | 283 | 283 | 358 | 30.0 min |
| **total** | 1558 | 1113 | **22,601** | **287.6 min** |

Music: **79 tracks / 189 min**, in the `ud1.bin`/`ud2.bin` gaps.

> **The names are the original source `.wav` filenames** (e.g.
> `AYA_SP_0001.wav`, `CAPEL_1_FV_0061.wav`, `BGM_24_BATTLE_SCENE.wav`), so the
> whole audio corpus ships with a human-readable inventory.

## 2. Codec: XMA2 (Xbox 360 hardware codec)

Each `AAC ` `WAVE` chunk is an **XMA2** stream:

| `WAVE` field | Meaning |
|---|---|
| `+0x10` data size | audio bytes |
| `+0x14` sample rate | per-sound (~48 kHz, detuned per sound) |
| `+0x18` play begin | XMA encoder delay (384) |
| `+0x20` block size | `0x8000` (`bytesPerBlock`) |
| `+0x24` total samples | multiple of 512 |
| `+0x2C` block count | `ceil(data_size / 0x8000)` |
| `+0x50` `strm` | channel count at `WAVE+0x60` (1 = mono, 2 = stereo) |
| `+0x1000` | **the XMA2 audio begins exactly 0x1000 into the chunk** |

Wrapping those bytes in the `XMA2WAVEFORMATEX` (format tag `0x0166`) makes
ffmpeg report `codec_name=xma2` and decode cleanly.

| Tool | Decode | Encode |
|---|---|---|
| ffmpeg 6.1 | ✅ | ❌ |
| vgmstream / ToWav | ✅ | ❌ |
| ReXGlue / Xenia `XmaDecoder` (used by the recomp) | ✅ | ❌ |
| Microsoft GDK/XDK `xma2encode.exe` / XACT | ✅ | ✅ (licensed/NDA) |

**There is no free/open-source XMA2 encoder.** This is the single hard
constraint for on-disk dubbing (see §5).

## 3. Which sounds are dialogue — and which character

Dialogue is identified by the **name markers** in the source `.wav` filename:

| Marker | Meaning | Dub? |
|---|---|---|
| `_SP_` | **speech** (story/cutscene dialogue) | **yes — main target** |
| `_FV_` | field voice (short in-world quips) | **yes** |
| `BTL` / `BATTLE` / `SITU` | battle / situational lines | **yes** |
| `_WALK_ _RUN_ _FALL_ _LANDING_ _SIT_ _STAND_ _JUMP_ _STEP_ _HIT_ _ATTACK_ …` | movement & combat foley | no |
| `SYSTEM_…`, `CAMP_…`, `GMK_…` | UI/menu/gimmick SFX | no |

Examples:

```
AYA_220_SP_ACT_06.wav        -> story speech, Aya
CAPEL_1_FV_0061.wav          -> field voice, Capel
SOLDIER_012_BTL_03.wav       -> battle line, Soldier
ENM_WOLF_005_ATTACK.wav      -> foley (no dub)
SYSTEM_001_DECISION.wav      -> menu SFX (no dub)
```

**Dub target: 3,149 voice lines, ≈36.9 minutes.** The bulk of the 22,601 sounds
is movement foley and monster SFX.

## 4. Extracting the audio

The disc containers are **NORM/MRON**. The vendored tool
`tools/vendor/pc-infiniteundiscovery/tools/mron.py` walks them.

```bash
# One SOND bank: structure, names, sizes, self-checks
cd extract/f2/all_d1ud1
python ../../../tools/vendor/pc-infiniteundiscovery/tools/aac.py info \
    000A4000_023_SOND.bin --limit 15

# Export every sound of a bank as RIFF-wrapped XMA2 (no re-encode)
python ../../../tools/vendor/pc-infiniteundiscovery/tools/aac.py xma \
    000A4000_023_SOND.bin /tmp/xma_out
ffprobe /tmp/xma_out/009_SYSTEM_008_SONG_CHANGE.xma | grep codec_name   # xma2

# Decode to WAV with ffmpeg (listening / transcription / re-recording)
ffmpeg -i /tmp/xma_out/009_SYSTEM_008_SONG_CHANGE.xma out.wav
```

Extract the whole container if needed (already done in `extract/f2/all_d1ud*`):

```bash
python tools/vendor/pc-infiniteundiscovery/tools/mron.py extract \
    extract/f2/run/EUROPE/assets/disc1/ud1.bin <outdir> \
    --offset <hex> --length <size> --decompress
```

> Some `SOND` resources are **SLZ-compressed** on disc (349 of the 1275 in
> `ud1.bin`); `--decompress` (or `mron.py`'s default) handles that.

## 5. Dubbing procedure

### Path B — PC recomp (recommended; **no asset is modified**)

The recomp decodes XMA **in software** (Xenia's `XmaDecoder`) and already hooks
guest functions at runtime (the same mechanism as the text hook). This makes a
dub possible **without an XMA2 encoder and without touching `ud1.bin`/`ud2.bin`**.

Procedure:

1. **Build the line list** — `tools/audio_inventory.py` produces
   `mod/audio/dialogue_to_dub.csv` (name → duration → speaker).
2. **Decode** each target `SOND` to WAV with `aac.py xma` + `ffmpeg` (or `aac.py
   wav`). This is the source to transcribe/re-record.
3. **Record/translate** the Spanish (or target-language) lines; export them as
   WAV/PCM **named exactly like the original** (`AYA_SP_0001.wav`, …) into a
   folder, e.g. `mod/audio/es/`.
4. **Substitute at runtime** — hook the audio submission path (the guest calls
   into XAudio2: `XAudioSubmitRenderDriverFrame`, `XMACreateContext`, …). Map the
   submitted buffer back to its `AAC ` `dirn` name and play the matching file
   from `mod/audio/es/` instead. Music and SFX are left untouched (mixed-language
   dub).
5. **Package** — ship `mod/audio/es/` + the hook in the same way the text mod
   ships `mod/translation/`.

> Status: steps 1–3 are fully supported by the tooling in this repo; step 4 is
> the runtime hook to be added (the same weak-alias mechanism as
> `translation_es.h`).

### Path A — on-disk (works on real hardware / RGH)

Required because the console decodes XMA **in hardware**, so the on-disk
bitstream must be valid XMA2:

1. Re-encode the new lines to **XMA2** (only Microsoft's GDK/XDK encoder can do
   this).
2. Repack each `AAC ` container (recompute the header total size, the playback
   offset, each `dirn` `WAVE` offset, each `WAVE`'s `data_size`/`block_count`),
   then the MRON archive entry table, then the `ud1.bin`/`ud2.bin` layout
   (2048-aligned), then the XDVDFS file sizes.
3. No checksums exist in `AAC `/MRON (only `default.xex` is signed), but the
   **PC recomp verifies `ud1.bin`/`ud2.bin` by SHA-256**, so a patched build must
   add the new hashes (or bypass the check). On real hardware use **RGH/JTAG**.

> Precedent: a community **undub** (Japanese voices, English text) exists and the
> recomp even supports a `USA-UNDUB` profile — but it *splices existing XMA2*
> from the Japanese release, so it needed no encoder. A **new-language** dub has
> no such source, which is exactly why Path B (recomp) is the practical route.

## 7. Limitations & open questions

- **XMA2 encoder** — none free; blocks on-disk dubbing.
- **Music location** — the music is in the inter-archive gaps (bare `AAC `
  runs); it is intentionally left untouched by a dialogue-only dub.
- **Archive index** — whether the engine uses a global index for `ud1.bin` (the
  high-entropy `0x16000` prefix) is unconfirmed; a full repack should be tested
  on the recomp first.
- **Speaker grouping** — the `SP`/`FV`/`BTL`/`SITU` classification is a
  filename heuristic; the voice-vs-vocal-SFX boundary is fuzzy.

## Resumen (ES)

- **Dónde está el audio:** en recursos **`SOND`** (contenedores `AAC ` de
  tri-Ace) dentro de `ud1.bin`/`ud2.bin`. La **música** va aparte, en los huecos
  entre archivos MRON. Los nombres son los `.wav` originales.
- **Códec:** **XMA2** (hardware de Xbox 360). Se decodifica con ffmpeg/vgmstream;
  **no existe codificador libre**.
- **Qué se dobla:** las líneas de voz se identifican por el nombre: `_SP_`
  (diálogo de historia), `_FV_` (voz de campo), `BTL`/`BATTLE`/`SITU` (batalla).
  En total **3 149 líneas / ~37 min**; el resto son efectos y foley.
- **Extraer:** `aac.py info/xma/wav` + `ffmpeg`.
- **Incorporar:** en el **recomp (PC)** por sustitución en runtime (por nombre de
  sonido, sin tocar assets ni codificar XMA); en **hardware real** solo
  re-codificando a XMA2 (encoder de Microsoft) y reconstruyendo contenedores +
  XDVDFS (RGH/JTAG).
- **Listado exhaustivo:** `mod/audio/dialogue_to_dub.csv` (generado con
  `tools/audio_inventory.py`).
